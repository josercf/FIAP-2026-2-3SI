O contrato em Python: Protocol, não classe base [3]

Em Java e C# o contrato é uma interface que as classes implementam explicitamente. Em Python moderno, typing.Protocol descreve o formato esperado sem obrigar herança: quem tiver os membros certos já cumpre o contrato.

from typing import Protocol, runtime_checkable

@dataclass(frozen=True)
class Cotacao:
    valor: float
    prazo_dias: int
    modalidade: str

@runtime_checkable
class EstrategiaFrete(Protocol):
    """Contrato que toda modalidade de frete precisa cumprir."""
    modalidade: str

    def cotar(self, distancia_km: float, peso_kg: float) -> Cotacao: ...
Por que isso importa

Nenhuma estratégia precisa importar o protocolo para cumpri-lo. O acoplamento vai na direção certa: quem depende do contrato é a rota, e não as implementações.

06 – Strategy x Factory
19

Quando o if está certo e o padrão está errado

Padrão aplicado onde não havia problema é custo puro: mais arquivos, mais indireção, mais tempo até um colega entender o fluxo. Três sinais de que a cadeia de if pode ficar.

O conjunto é fechado

Dois ramos que existem por definição do domínio e não vão crescer, como débito e crédito num lançamento contábil.

Os ramos são de uma linha

Se cada caso é uma expressão, uma classe por caso troca clareza por cerimônia. Um dicionário de funções já resolve.

Não há variação por cliente

Strategy paga quando alguém de fora do seu módulo precisa acrescentar um algoritmo. Sem essa necessidade, é indireção sem retorno.

O critério honesto

A pergunta não é "isso é um padrão conhecido?", e sim "quantos arquivos mudam quando o negócio mudar?". No frete da LogiTech a resposta era a rota inteira, e por isso o Strategy se paga.

06 – Decorator: a Ideia
26

O primeiro decorador: ComLog [4]

export class ComLog implements Enviador {
  constructor(private readonly interno: Enviador,
              private readonly log: Registrador) {}

  get canal(): string { return this.interno.canal; }   // se passa pelo embrulhado

  async enviar(notificacao: Notificacao): Promise<ResultadoEnvio> {
    this.log.registrar(`tentativa canal=${this.canal} destinatario=...`);
    try {
      const resultado = await this.interno.enviar(notificacao);
      this.log.registrar(`sucesso canal=${this.canal} identificador=...`);
      return resultado;                                 // devolve intacto
    } catch (erro) {
      const motivo = erro instanceof Error ? erro.message : String(erro);
      this.log.registrar(`falha canal=${this.canal} motivo=${motivo}`);
      throw erro;                                       // relança, não engole
    }
  }
}
As duas linhas que separam decorador de remendo

return resultado sem alterar nada, e throw erro em vez de engolir. Decorador observa e acrescenta; quem decide o que fazer com a falha é a camada de cima. O instanceof Error não é enfeite: com strict ligado, o TypeScript tipa o capturado como unknown e recusa erro.message direto.

06 – Decorator: Empilhamento
28

O segundo decorador: ComRetentativa [5]

export class ComRetentativa implements Enviador {
  constructor(private readonly interno: Enviador,
              private readonly maxTentativas = 3,
              private readonly esperaMs = 0) {}

  async enviar(notificacao: Notificacao): Promise<ResultadoEnvio> {
    let ultimoErro: unknown;
    for (let tentativa = 1; tentativa <= this.maxTentativas; tentativa += 1) {
      try {
        const resultado = await this.interno.enviar(notificacao);
        return { ...resultado, tentativas: tentativa };
      } catch (erro) {
        ultimoErro = erro;
        if (tentativa < this.maxTentativas && this.esperaMs > 0) {
          await espere(this.esperaMs);       // await, não sleep bloqueante
        }
      }
    }
    throw ultimoErro;
  }
}

O await espere(...) devolve o controle ao event loop durante a espera. Um sleep bloqueante aqui congelaria as outras notificações em curso: é exatamente a armadilha do modelo assíncrono do início da aula.

O erro clássico: bloquear o event loop [5]

O modelo do event loop cobra um preço: uma única linha bloqueante trava o serviço inteiro, e não só a requisição que a executou. Em Java, aquela thread travaria sozinha; aqui, travam todas.

Trava o serviço inteiro

import time, requests

@app.post("/api/v1/frete/cotacao")
def cotar(pedido):
    time.sleep(0.2)            # bloqueia
    r = requests.get(URL)      # bloqueia
    return calcular(r.json())

Devolve o controle ao laço

import asyncio, httpx

@app.post("/api/v1/frete/cotacao")
async def cotar(pedido):
    await asyncio.sleep(0.2)
    async with httpx.AsyncClient() as c:
        r = await c.get(URL)
    return calcular(r.json())
A regra de bolso

Dentro de uma função async, toda espera precisa ter await na frente. Biblioteca sem versão assíncrona vai para um thread pool, nunca direto no laço: no FastAPI, rota declarada com def comum já roda em thread separada, e é a saída de emergência quando a biblioteca é síncrona.

  • A Ele concentra todos os cálculos em uma função só, mais fácil de editar quando surge uma modalidade nova.
  • B Ele encapsula cada algoritmo em uma classe que cumpre um contrato comum, e a modalidade nova entra como classe e registro, sem modificar o código que já usava as antigas.
  • C Ele obriga toda modalidade a herdar de uma classe base abstrata, que é reaberta a cada acréscimo.
  • D Ele adia a escolha do cálculo para o banco de dados, tirando a decisão do código da aplicação.
