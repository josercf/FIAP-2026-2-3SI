07 – Anatomia do Compose
7

Anatomia do docker-compose.yml [1]

name: logitech          # nome do projeto

services:               # os containers
  postgres:
    image: postgres:16-alpine
    environment: { POSTGRES_DB: logitech }
    volumes: [logitech-postgres:/var/lib/...]
    networks: [logitech-net]
    mem_limit: 256m
    healthcheck: { test: [...] }

networks:               # as redes
  logitech-net: { external: true }

volumes:                # os volumes nomeados
  logitech-postgres: { name: logitech-postgres }
BlocoResponde a
nameComo o Compose vai prefixar containers, redes e volumes deste projeto
servicesQuais processos existem, de onde vem a imagem e como cada um é configurado
networksEm que redes eles se enxergam, e quais já existiam antes
volumesOnde mora o dado que precisa sobreviver ao container

Não existe mais version: no topo. Ela era da era do docker-compose com hífen; a Compose Specification atual ignora esse campo e avisa que ele é obsoleto.

Um comando de saúde para quatro linguagens

O teste roda dentro do container, então ele só pode usar o que aquela imagem tem. As oito imagens do laboratório são Alpine, e o Alpine traz wget no BusyBox: um comando só serve para Java, C#, Python e Node.

  interval: 10s
  timeout: 4s
  retries: 6
  start_period: 25s

07 – Variáveis e Volumes
17

Volumes: o que o Compose cria e o que ele apenas usa [5]

Gerenciado pelo Compose

volumes:
  logitech-postgres:
    name: logitech-postgres

Nasce hoje, junto com o banco. O Compose cria no up e destrói no down -v. Ciclo de vida amarrado ao projeto.

Externo, herdado da Aula 03

volumes:
  logitech-telemetria:
    external: true

Já existia antes deste arquivo, criado à mão com docker volume create. O Compose usa e não remove nem com down -v.

A rede logitech-net segue a mesma lógica: external: true, porque é a mesma que vocês criaram à mão na Aula 03. A regra que vale para os dois: o que nasce com o projeto, o projeto gerencia; o que é anterior a ele, ele apenas usa.

Cuidado com dado de produção

Um docker compose down -v distraído apaga todo volume gerenciado. Volume de banco em ambiente compartilhado tende a ser declarado external exatamente para não morrer por engano.

07 – AI Gateway
22

Cinco serviços, dez integrações, cinco chaves espalhadas

A conta que ninguém faz

Com N serviços e M provedores são N vezes M integrações; com gateway, N mais M. E só no segundo caso existe um lugar capaz de responder quanto a empresa gastou com IA no mês.

07 – AI Gateway
23

As cinco responsabilidades de um AI Gateway [6]

1. Fachada única

Um endereço, um formato de requisição. Quem chama não sabe quantos provedores existem nem qual foi usado.

2. Roteamento

Qual provedor atende esta chamada: por custo, por qualidade, por conformidade ou pelo tamanho da pergunta.

3. Fallback

O preferido caiu, e a operação não pode parar. A fila continua, e a troca fica registrada.

4. Limite de taxa

Um laço com defeito em um serviço não pode consumir em dez segundos a cota que os outros sete precisam no mês.

5. Cache

A chamada mais barata e mais rápida é a que não acontece. Pergunta repetida não vai ao modelo duas vezes.

E a que justifica tudo

Observabilidade. Sem gateway ninguém responde quanto a empresa gasta com IA, nem quanto do tráfego o cache já economizou.

07 – AI Gateway
24

Facade: uma porta de entrada, complexidade escondida [7]

class GatewayDeIA:
    """A fachada. Uma porta para toda a IA."""

    async def responder(self, pergunta, modelo=None,
                        cliente="anonimo"):
        self.limitador.permitir(cliente)      # 1
        em_cache, tipo, nota = \
            self.cache.consultar(pergunta)    # 2
        if em_cache is not None:
            return ...                        # nem sai da rede

        ordem = self.estrategia.ordenar(      # 3
            list(self.provedores), pergunta)

        for provedor in ordem:                # 4
            try:
                return await provedor.responder(pergunta)
            except ProvedorIndisponivel:
                ...                           # fallback

Repare no que não está aqui: nenhum if provedor == "openai", nenhuma URL, nenhuma chave. A fachada orquestra; ela não conhece nenhum provedor por nome.

07 – Facade e Strategy
25

Strategy: a decisão sai do if e vira um objeto [7]

Sem Strategy

if politica == "barato":
    ordem = [local, remoto]
elif politica == "qualidade":
    ordem = [remoto, local]
elif politica == "conformidade":
    ordem = [local]
elif politica == "por_tamanho":
    ordem = [local] if len(p) < 280 else [remoto]
# a quinta politica entra aqui, editando
# um metodo que ja funcionava

Cada política nova mexe em código testado. É a violação do OCP que a Aula 05 nomeou.

Com Strategy

class SomenteLocal:
    nome = "somente-local"

    def ordenar(self, provedores, pergunta):
        return [p for p in provedores
                if p.nome == "local"]

ESTRATEGIAS = {
    PreferirRemoto.nome: PreferirRemoto,
    PreferirLocal.nome:  PreferirLocal,
    SomenteLocal.nome:   SomenteLocal,
    PorTamanhoDaPergunta.nome: PorTamanhoDaPergunta,
}

Política nova é classe nova mais uma linha no registro. A fachada não muda.

Por que isto é Strategy, e não configuração

A política por-tamanho decide a cada requisição, olhando a pergunta. Uma lista ordenada em arquivo de configuração não faria isso: só um objeto com comportamento faz.

07 – Facade e Strategy
26

Dois padrões no mesmo serviço, com papéis diferentes

A confusão mais comum da noite é achar que os dois fazem a mesma coisa porque aparecem juntos. Eles resolvem problemas opostos, e é isso que os torna complementares.

FacadeStrategy
ProblemaO cliente teria que conhecer e coordenar cinco partesO comportamento precisa mudar sem editar quem o usa
IntençãoSimplificar: uma interface no lugar de muitasVariar: várias implementações da mesma interface
QuantidadeUma fachada para o subsistema inteiroUma classe por política, e o registro delas
Quem escolheNinguém: a fachada é sempre a mesmaConfiguração, em LOGITECH_IA_ESTRATEGIA
No gatewayGatewayDeIA, a única classe que os outros serviços conhecemEstrategiaDeRoteamento, decidindo a ordem de tentativa
Se você tirarCada serviço volta a montar cache, limite e fallback por conta própriaVolta a cadeia de if, e cada política nova mexe em código testado
Como decidir em uma frase

Facade responde "por onde se entra"; Strategy responde "o que acontece lá dentro desta vez". Os provedores também são Strategy: mesma interface, implementações trocáveis.

07 – Facade e Strategy
27

As quatro políticas de roteamento do laboratório

PolíticaOrdem de tentativaQuando a LogiTech usaria
preferir-remotoremoto, depois localPadrão. O modelo grande responde melhor ao atendimento, e o local existe para a operação não parar
preferir-locallocal, depois remotoVolume alto e pergunta simples: custo e latência mandam
somente-localsó localA pergunta carrega dado de cliente e nada pode sair da rede da empresa
por-tamanhodecide a cada chamadaPergunta curta vai ao local; pergunta longa, com contexto, justifica o custo do remoto

somente-local não "prefere" o local: ele remove o remoto da lista. A diferença é de engenharia, não de estilo. Política de conformidade que apenas ordena preferências continua deixando o dado sair quando o preferido falha. Preferência não é controle.

Trocar de política

Uma linha no docker-compose.yml: LOGITECH_IA_ESTRATEGIA: somente-local. Nenhuma imagem é reconstruída, nenhum código é tocado, nenhum serviço cliente fica sabendo.

07 – Facade e Strategy
28

Fallback: a fila continua quando o preferido cai

Fallback silencioso não é fallback bom

Se o cliente não percebe, ótimo. Se ninguém percebe, você acaba de rodar meses no provedor de contingência sem saber. Por isso a troca vai para o log e para /v1/metricas.

07 – Fallback e Cache
29

Fallback de verdade, não encenado

O planejamento pedia fallback entre um provedor pago e modelos locais. Não há chave paga para a turma, e a saída fácil seria simular a falha com um if. A decisão registrada em ADR foi outra.

O que não fizemos

# fallback de mentira
if SIMULAR_FALHA_DO_REMOTO:
    print("fingindo que o remoto caiu")
    return provedor_local.responder(p)

Passa a impressão certa e ensina a coisa errada: nenhum caminho de erro real é exercitado, e o dia em que o provedor cair de verdade será a primeira vez que o código roda.

O que o laboratório faz

def por_que_indisponivel(self):
    if not self.chave:
        return ("credencial ausente: a variavel "
                "LOGITECH_IA_REMOTA_CHAVE esta vazia")
    return None
# a chamada levanta ProvedorIndisponivel,
# e a fachada trata como trataria um 503

A falha é real e o caminho de erro é o mesmo de uma indisponibilidade de produção. Preencher a chave no .env liga o remoto sem tocar em código.

Detalhe de engenharia que vale a pena notar

O provedor remoto falha antes de abrir socket. Não se manda requisição sabidamente inválida para um provedor pago só para "tentar": isso queima cota, polui métrica e atrasa o fallback.

07 – Fallback e Cache
32

Caching semântico: acerto sem igualdade de texto [8]

Cache comum guarda por chave exata: um espaço a mais e é erro de cache. Caching semântico guarda por significado, e acerta perguntas escritas de formas diferentes.

07 – Fallback e Cache
33

Semântico de verdade usa vetores. O laboratório usa palavras.

Como se faz em produção

A pergunta vira um vetor de embeddings, e a busca acontece num banco vetorial por similaridade de cosseno.

"Onde está meu pedido" e "cadê minha encomenda" viram vetores vizinhos sem uma palavra em comum. Exige um modelo de embeddings e um banco vetorial.

Como o laboratório faz

Similaridade lexical, por índice de Jaccard sobre as palavras normalizadas: interseção dividida por união, com limiar de 0,72.

Pega variação de acento, caixa, pontuação e ordem das palavras. Não pega sinônimo. Roda sem modelo de embeddings e sem banco vetorial.

Na validação do laboratório, "Responda em uma frase curta: o que faz uma transportadora de cargas?" e "O que faz uma transportadora de cargas? Responda em uma frase curta." foram servidas pela mesma entrada do cache, por similaridade. O mesmo conjunto de palavras, outra ordem.

Por que dizer isso em vez de esconder

O mecanismo é idêntico: normalizar, medir distância, aceitar acima do limiar. Só a métrica de distância é mais simples. O banco vetorial chega no Módulo III, e aí a troca é de uma classe, não da arquitetura.

Quiz de Verificação

O que é o Caching Semântico em um AI Gateway e como ele reduz custos operacionais?
  • A É guardar a resposta apenas quando o texto da pergunta é idêntico, caractere por caractere, ao de uma pergunta já respondida.
  • B É um cache que armazena respostas com base na similaridade de significado entre as perguntas, evitando novas chamadas ao provedor para perguntas conceitualmente iguais escritas de formas diferentes.
  • C É comprimir o histórico da conversa antes de enviá-lo ao modelo, reduzindo o número de tokens cobrados em cada chamada.
  • D É manter o modelo carregado na memória entre as chamadas, para não pagar o tempo de carga a cada requisição.

Aula 08, 22/09: Function Calling e Command Pattern
