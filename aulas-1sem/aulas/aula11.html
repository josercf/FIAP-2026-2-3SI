Desafio do Mini Mundo: a sala de controle da LogiTech

O Portal da Aula 10 é usado por quem comprou: abre, consulta um pedido, fecha. O painel de hoje é usado por quem opera, e fica aberto a noite inteira.

1. A frota não para de emitir

Posição de caminhão não é uma resposta que chega uma vez. É um fluxo que começa quando o operador abre o painel e não termina nunca. Uma Promise resolve uma vez e acabou.

2. Ele filtra com o fluxo correndo

Clicou em PR: a tabela refiltra na hora, sem esperar o próximo caminhão. E o próximo caminhão respeita a UF já escolhida. São duas fontes de verdade que precisam ser cruzadas.

3. A consulta demora e ele continua digitando

Cada tecla dispara uma consulta de 800 ms. Digitar 1003 são quatro consultas correndo juntas, e a resposta do 100 pode chegar depois e sobrescrever a tela.

Repare no que as três dores têm em comum: tempo. Não é "buscar um dado", é "lidar com dados que chegam em momentos diferentes e disputam a mesma tela". Esse é exatamente o problema que o Observer Pattern resolve, e o RxJS é o Observer Pattern com uma biblioteca de operadores em cima.

Standalone Components: o fim do NgModule [1]

Por doze anos, um componente Angular só existia se estivesse declarado em um módulo, e só enxergava o que aquele módulo importasse. O módulo era um terceiro arquivo que ninguém lia e todo mundo tinha que manter em dia.

Antes: três arquivos para uma tela

@NgModule({
  declarations: [FrotaComponent],
  imports: [CommonModule, HttpClientModule],
  exports: [FrotaComponent],
})
export class FrotaModule {}

@Component({ selector: 'app-frota' })
export class FrotaComponent {}

Hoje: o componente declara o que usa

@Component({
  selector: 'app-frota',
  imports: [AsyncPipe],
  template: `...`,
})
export class FrotaComponent {}

O que se ganha

A dependência fica ao lado de quem a usa. Apagar o componente apaga as importações dele junto, e o carregamento sob demanda passa a ser por componente e não por módulo.

O que isso tem a ver com o React

É a mesma unidade de composição da Aula 10: o componente. O Angular deu meia-volta e foi buscar exatamente o ponto em que o React sempre esteve, sem abrir mão da infraestrutura que ele traz por baixo.

Registrar: um token, quando não há classe

export const ABRIR_FONTE_DE_EVENTOS =
  new InjectionToken<AbrirFonteDeEventos>(
    'ABRIR_FONTE_DE_EVENTOS',
    { providedIn: 'root',
      factory: () => (url: string) => new EventSource(url) },
  );

Pedir: sempre igual

private readonly abrirFonte = inject(ABRIR_FONTE_DE_EVENTOS);

O InjectionToken existe porque nem toda dependência é uma classe. Abrir uma conexão SSE é uma função, e função não tem tipo em tempo de execução para servir de chave. O token é um objeto com identidade própria, que sobrevive à minificação e não depende do nome de nada.

11 – Observable Frio

Um Observable escrito à mão, sobre o SSE do painel [2]

private criarFluxoDeEventos(): Observable<Posicao> {
  return new Observable<Posicao>((inscrito) => {          // 1. roda a cada subscribe
    const fonte = this.abrirFonte(this.urlDeEventos);      //    http://localhost:3000/api/v1/eventos

    fonte.addEventListener('posicao', (evento) => {        // 2. o Observer Pattern do slide anterior
      inscrito.next(JSON.parse(evento.data) as Posicao);   //    next: mais um valor no fluxo
    });

    fonte.addEventListener('error', () => {
      inscrito.error(new Error('fluxo de telemetria interrompido'));
    });

    return () => fonte.close();                            // 3. teardown: roda no unsubscribe
  });
}

1. A função é a receita

Ela não roda na criação. Roda uma vez por inscrito, e é isso que faz o Observable ser frio.

2. Três canais, não um

next para valor, error para falha e complete para fim. Aqui não há complete: a frota não termina.

3. O retorno é o desfazer

A função devolvida é chamada no unsubscribe. É a metade que todo mundo esquece.

Os quatro que parecem iguais, e o que fazem com a corrida [2]

OperadorO que faz com a inscrição anteriorQuando é o certo, na LogiTech
switchMapCancela e troca pela novaBusca de fatura enquanto se digita. Só a última pergunta interessa.
mergeMapDeixa correr junto, sem ordemAvisar 400 clientes sobre atraso na entrega. Todas importam e a ordem não.
concatMapEnfileira e espera a anterior terminarGravar confirmações de entrega em sequência. Todas importam e a ordem importa.
exhaustMapIgnora a nova enquanto a anterior correBotão de emitir fatura. O duplo clique não pode emitir duas notas.

Os quatro têm a mesma assinatura e trocar um pelo outro compila sem reclamar. É por isso que a escolha errada passa em revisão de código e só aparece em produção, no relato de um usuário que jura ter visto o dado de outro pedido. A pergunta que resolve é sempre a mesma: se chegar um valor novo com o anterior ainda em voo, o que deve acontecer com o anterior?

Quiz de Verificação

Como o Observer Pattern implementado pelo RxJS difere do modelo tradicional de requisição e resposta com Promises?
  • A Não difere: Observable é apenas o nome que o Angular deu para Promise, com a mesma semântica.
  • B A Promise trata um único evento futuro. O Observable é um fluxo que pode emitir zero, um ou muitos valores ao longo do tempo, e por isso aceita operadores que transformam os valores em trânsito.
  • C O Observable é sempre mais rápido, porque não usa o event loop.
  • D A Promise só funciona com HTTP; o Observable só funciona com WebSocket.

O que vem: do relacional ao vetorial, na Aula 12

20/10: PostgreSQL, RAG e MCP

psql dentro do container, e o primeiro contato de vocês com SQL vai ser lendo a SQL que o ORM das Aulas 05 e 06 escreveu por vocês. Depois DDL à mão, JOIN, e só então a busca semântica com pgvector, entrando como mais um ORDER BY. No fim, um servidor MCP expondo a API de Pedidos para agentes parceiros.

O que de hoje reaparece lá

O HttpClient com interceptador vira o cliente do pipeline de RAG. E o switchMap volta como o operador certo para uma caixa de busca semântica, onde o custo de cada consulta é bem maior que os 800 ms de hoje.

A espiral continua

O painel de hoje e o portal da Aula 10 são as duas telas que o CP3 cobra junto com RAG e MCP. Guardem o fork: na Aula 14 essas mesmas rotas passam a exigir autenticação, e vocês vão descobrir o que um interceptador tem a ver com isso.
