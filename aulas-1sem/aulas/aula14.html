OAuth 2.0, OIDC e JWT

OAuth 2.0

Framework de Autorização. Permite que um aplicativo acesse recursos de um usuário sem expor sua senha.

OpenID Connect (OIDC)

Camada de Identidade sobre OAuth 2.0. Foca na Autenticação (Quem é o usuário?).

JWT (JSON Web Token)

Padrão aberto (RFC 7519) para transmitir dados de forma compacta e segura (Header, Payload, Signature).

RBAC

Role-Based Access Control. Controle de acesso baseado em papéis (Admin, User, Manager).

Git Worktrees II (Revisão Prática)

Como isolar a implementação de segurança sem atrapalhar o desenvolvimento da branch principal?

# Adicionando uma nova worktree para a feature de segurança
git worktree add ../logitech-security feature/auth-jwt

# Verificando as worktrees ativas
git worktree list

# Removendo após finalizar (na pasta principal)
git worktree remove ../logitech-security

Quiz #1 (Fixação do Bloco 1)

Qual a diferença fundamental entre OAuth 2.0 e OpenID Connect (OIDC)?
  • A Ambos servem exclusivamente para criptografia de dados em trânsito
  • B OAuth 2.0 é para delegação de Autorização, enquanto OIDC adiciona uma camada de Autenticação de Identidade
  • C OIDC substitui os JWTs, enquanto OAuth 2.0 obrigatoriamente os utiliza
  • D OAuth 2.0 lida com senhas de usuário, enquanto OIDC lida com biometria

Quiz #2 (Retorno do Intervalo)

O que acontece se o Payload de um JWT for alterado maliciosamente por um atacante após ter sido emitido pelo servidor?
  • A O servidor processará os dados alterados normalmente, pois o JWT não é criptografado.
  • B A Assinatura (Signature) se tornará inválida, e o servidor rejeitará o token.
  • C O JWT acionará um alerta automático para o Banco de Dados.
  • D O navegador bloqueará a requisição por causa da política CORS.

Quiz #3

No contexto do Mini Mundo LogiTech, implementamos RBAC. Qual o propósito principal disso?
  • A Garantir que a senha do usuário seja forte e complexa.
  • B Proteger o banco de dados contra ataques de SQL Injection.
  • C Garantir que usuários diferentes (ex: Motorista, Analista) tenham acessos restritos baseados em seus papéis.
  • D Garantir que a comunicação HTTP seja feita via TLS/SSL.
