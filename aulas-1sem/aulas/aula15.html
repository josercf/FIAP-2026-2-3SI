O Novo Paradigma de Segurança

LLM01: Prompt Injection

Atacante manipula o LLM via entradas criativas (prompts) para ignorar instruções originais e executar ações maliciosas.

LLM02: Insecure Output Handling

Confiar cegamente na saída do LLM. Ex: O LLM gera um código SQL malicioso e a aplicação executa no banco.

LLM06: Sensitive Information Disclosure

O LLM memoriza dados sensíveis (PII, senhas) no treinamento e os revela para outros usuários em respostas futuras.

Defesa em Profundidade

Sempre sanitize inputs e outputs. Use guardrails, RBAC nas APIs de integração (RAG) e AI Gateways.

Vulnerability Scanning com Trivy

A LogiTech Enterprise roda tudo em Containers (Docker). Como garantir que as imagens base não tenham falhas graves (CVEs)?

# Instalando Trivy (Ex: via Homebrew no Mac)
brew install aquasecurity/trivy/trivy

# Escaneando uma imagem Docker local
trivy image node:18-alpine

# Escaneando arquivos de configuração (Dockerfile, Terraform, K8s)
trivy config ./Dockerfile

DevSecOps: O Trivy é fundamental para a esteira CI/CD, bloqueando deploys de imagens com vulnerabilidades CRITICAL ou HIGH.

Quiz #1 (Fixação do Bloco 1)

O que caracteriza o ataque de 'Prompt Injection' de acordo com o OWASP Top 10 para LLMs?
  • A Injetar comandos SQL diretamente no banco de dados de vetores (Vector DB)
  • B Manipular a entrada de texto do usuário para forçar o LLM a desobedecer suas instruções de sistema (System Prompts) originais
  • C Infectar o modelo LLM com vírus durante o seu download da internet
  • D Interromper o tráfego de rede (DDoS) do provedor de inteligência artificial

Quiz #2 (Retorno do Intervalo)

Para que serve primordialmente a ferramenta 'Trivy' em ambientes corporativos de DevSecOps?
  • A Para formatar o código fonte automaticamente (Linter) e arrumar erros de sintaxe
  • B Para construir (buildar) imagens Docker mais rapidamente, substituindo o comando docker build
  • C Para escanear imagens de containers, sistemas de arquivos e repositórios em busca de vulnerabilidades de segurança (CVEs)
  • D Para gerenciar o balanceamento de carga do Kubernetes e provisionar novos nós

Quiz #3

Qual a melhor estratégia para mitigar 'Insecure Output Handling' ao integrar um LLM na LogiTech?
  • A Confiar na saída do LLM caso a temperatura do modelo esteja definida como 0 (Zero)
  • B Tratar o texto gerado pelo LLM como 'untrusted input' (não confiável) e aplicar sanitização antes de enviá-lo ao banco ou ao navegador do usuário
  • C Forçar o usuário a digitar uma senha forte antes de conversar com o bot
  • D Utilizar exclusivamente modelos open-source ao invés de APIs comerciais
